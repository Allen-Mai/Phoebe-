# 网页测试版

## 这是什么

一个**零依赖的单文件网页**，用来在安装 Logseq 之前先试一遍整套记录方式。

**打开方式**：双击 `index.html`（Chrome / Edge）。

不需要 Node、不需要 Python、不需要服务器、不需要联网。

## 能试什么

**默认打开就是表格视图** —— 标题横过来当表头，一行一条记录，不用一屏一屏往下翻。

### 表格视图（默认）

| 标签 | 是什么 |
|---|---|
| **日记表** | 行 = 每一天，列 = `今天做了什么` / `工作和进展` / `感受 / 状态` / `明天要做` |
| **手册表** | 行 = 每个手册页面，列 = 各页面里的 `##` 标题 |

表头是**自动**从内容里的 `##` 二级标题生成的 —— 你在日记里写 `## 今天做了什么`，
它就成为一列。想加一列，就在日记里多写一个 `##` 小标题。

### 其他

| 功能 | 在哪 |
|---|---|
| 单个页面的表格视图 | 点左侧任意一页 → 默认也是表格（该页的标题当表头）|
| 切回原文 / 编辑 | 页面右上「原文 / 表格」切换、「编辑」按钮 |
| 日记 ↔ 页面互相跳转 | 单元格里的 `[[示例项目]]`、`[[张三]]` 点一下就跳 |
| 反向链接（谁提到过我） | 右侧「反向链接」面板 |
| 待办自动汇总 | 左侧「✅ 待办总览」；表格里 `{{query}}` 会直接展开成结果 |
| 本周工作自动汇总 | 左侧「📅 本周工作」 |
| 全文搜索 | 左侧「🔍 搜索」 |
| 字数热力图 / 连续天数 | 左侧「📊 统计」 |
| 编辑 + 下载 .md | 页面右上「编辑」按钮 |

右侧「指向的页面」里如果显示红色，说明那个页面还不存在 —— 点它会**自动创建**。

## 出错了怎么办（重要）

因为这份文件交付时**没有在作者本机运行验证过**，所以把排查手段做进了页面里：

**1. 顶部横幅会显示自检结果**

打开后右上角会显示 `✅ 自检：12 项通过` 或 `❌ 自检：N 项失败`。
点它（或点「查看自检结果」）就能看到每一项的详细结果。

- **全部通过** → 程序没问题。你看到的内容不对，是视图选择或演示数据的问题，直接说期望看到什么。
- **有失败项** → 把标着「❌ 失败」的那几行**整段复制**发给作者。

**2. 页面报错不会白屏**

如果脚本有语法错误或运行时异常，页面顶部会出现一个**红色区域**，
里面是确切的错误信息和出错位置。把那整段文字复制发出来即可。

（原理：错误处理脚本放在所有脚本之前注册，所以连语法错误也能捕获。）

## Emoji 是自动配的

表格表头、正文里的 `##` 标题、左侧导航，都会自动带一个 emoji：

- **先按关键词匹配**：`今天做了什么` → 📝、`工作和进展` → 💼、`待办` → ✅、`风险 / 卡点` → ⚠️、
  `关键决策记录` → 🧸、`踩过的坑` → 🕳️ …
- **匹配不到**就用标题文字的**哈希**挑一个（🌸🎀🧸🍓🐰…）。
  用哈希而不是随机数，是为了让**同一个标题每次刷新都是同一个 emoji**，不会乱跳。

页面大标题的 emoji 不看关键词，而是看页面顶部的 `type::` 属性：

| `type::` | emoji |
|---|---|
| `项目` | 🎀 |
| `人物` | 🐰 |
| `经验` | 💡 |
| `周报` | 📮 |
| `索引` | 🌸 |
| 日记（`journals/`） | 📔 |
| 其它 | 📄 |

### 想自己控制

1. **加规则**：在 `index.html` 里搜 `EMOJI_RULES`，加一行 `[/你的关键词/, '🍓'],` 即可
   （规则从上往下匹配，越靠前优先级越高，所以要把更具体的放前面）。
2. **完全关掉自动加**：搜 `EMOJI_AUTO`，改成 `false`。
   这时你可以直接在标题里手写 emoji（如 `## 🍓 今天做了什么`），不会出现两个 emoji。

> 为什么要留第 2 条：如果你手写 emoji 又开着自动匹配，标题会变成 `📝 🍓 今天做了什么` 两个 emoji。
> 关掉 `EMOJI_AUTO` 就干净了。

## 必须知道的三件事

1. **修改不会写到磁盘。** 编辑内容保存在浏览器的 localStorage 里，要拿到文件请点「下载 .md」。
2. **它是演示界面，不是 Logseq。** 真实使用要按 `../操作手册.md` 装 Logseq OG。
   这个网页只用来判断「这套记录方式合不合我的习惯」。
3. **演示数据的日期自动对齐到今天**，所以打开就能看到 3 天连续记录和热力图。
   顶部的「清空我的修改」只清浏览器数据，不影响磁盘文件。

## 数据从哪来

演示图库直接内嵌在 `index.html` 里，用 `<script type="text/plain" class="vault-file" data-path="...">`
的形式存放，每个块就是一个 `.md` 文件。

`@TODAY@` / `@TODAY-1@` / `@TODAY-2@` 在加载时会替换成真实日期，
所以**演示数据的日期永远对齐到今天**，打开就有 3 天连续记录。

> **同一份演示内容也放在 `../graph/` 里**（真实图库骨架），两边是镜像关系。
> 改了一边记得改另一边，否则网页和真实图库会对不上。

⚠️ `../graph/pages/` 下的 `示例项目.md`、`张三.md`、`数据库迁移操作步骤.md`
和 `journals/2026_10_05.md`、`2026_10_06.md` 是**演示数据**，正式使用时删掉即可。
留着它们是因为：`2026_10_07.md` 里链接了 `[[示例项目]]` 和 `[[张三]]`，
如果这些页面不存在，在 Logseq 里会变成空页面。

## 和真实图库的差别

| | 网页测试版 | Logseq 真实使用 |
|---|---|---|
| 数据落盘 | ❌ 只有 localStorage + 手动下载 | ✅ 直接就是磁盘上的 `.md` |
| 同步 | ❌ 无 | ✅ Syncthing（Win↔Android）+ Git（iPhone 只读） |
| 查询语法 | 只实现了 `(task …)` 与 `(between -Nd today)` 两种 | 完整 Logseq 查询 |
| PDF 导出 | ❌ | ✅ 插件 |
